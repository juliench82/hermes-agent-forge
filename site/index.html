Three steps

  1. 1

    Install Forge

    Run the activation command. Hermes fetches a single signed SKILL.md over HTTPS — nothing is cloned, nothing is executed by a shell.

  2. 2

    Open Hermes

    CLI or Desktop — the installed skill registers itself as the /forge slash command automatically.

  3. 3

    Type /forge

    Describe your goal. Forge proposes a team of 3, 5, or 7 profiles, shows the full plan, and waits for your approval before changing anything.

What Forge does

Forge is an onboarding skill, not a hosted service. This website distributes the activation artifact only — Hermes performs the onboarding locally on your machine. Inside the /forge session, Hermes analyzes your use case, proposes profile names, responsibilities, skills, and collaboration boundaries, then — only after you approve — creates the profiles, generates each role's SOUL.md, installs the agreed skills, updates config.yaml with values you accepted, and validates the result before reporting what was created.

Your existing main/orchestrator profile stays the single hard-coded baseline. Every other profile is generated dynamically from your goals — no industry presets, no fixed mappings.

Security & trust

  • No repository cloning. The GitHub repository is source code, not the installer. A fresh Hermes never needs to point at a repo URL.
  • Plan before writes. /forge always shows the complete team plan and asks for explicit approval before creating or modifying profiles, files, or configuration.
  • No API keys collected here. This site never asks for credentials, and Forge never embeds secrets in generated files.
  • User-space only. Installation lives under ~/.hermes. No sudo, no privileged shell, no curl | bash requirement.
  • Scoped side effects. Third-party skills and external services are called out individually and approved separately.
