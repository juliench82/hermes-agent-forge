# starter-guide.md — Plain-Language Guide

This guide is for regular people in a company. You do not need to be technical to use Hermes.

## What Hermes does
Hermes is a control room that automates repetitive work. You describe a task you do over and over, and Hermes turns it into an automation that runs for you.

## How it works under the hood
When you talk to Hermes, one assistant listens to your request. Behind the scenes, it follows a set of role-based instructions to break your request into steps: understanding what you need, designing an approach, building it, checking the result, and delivering something useful back to you.

You do not see these steps as separate tools or separate apps. You see one Hermes that handles your request from start to finish.

## What you provide
- A short description of the repetitive task.
- Any file, list, or access the task needs.
- A simple answer when Hermes asks a clarifying question.

## What Hermes returns
A useful finished result, such as:
- an email with compiled invoices
- a report
- a notification
- a generated workflow result
- a background automation outcome

Hermes does not hand you raw code and stop. It delivers something you can actually use.

## Examples of automation requests
- "Every Friday, email me a summary of unpaid invoices."
- "When a new support ticket comes in, sort it and notify the right person."
- "Compile the monthly expense report and send it to finance."
- "Watch this folder and rename new files by date."

## Simple expectations and limitations
- Hermes asks simple questions only, in plain language.
- Hermes will not run forbidden or unsafe operations.
- Some tasks may need a one-time setup step.
- Hermes keeps your context compact so it does not bloat over time.
- In the default setup, one Hermes assistant handles everything internally using role-based skills. A more advanced setup with fully separate agents is possible but requires additional configuration.
